Gembul Agent

Privacy Policy

Last updated 8 November 2026

Gembul Agent is a self-hosted office dashboard that runs agent tasks on the owner's own Google account. This page explains exactly what the service stores and what it does with it. There is one user: the person who deployed it.

What the service stores

  • The email address of the Google account that signed in. It is shown in the interface so you can confirm which account is active.
  • An OAuth access token and refresh token issued by Google for that account.
  • The Cloud Code project identifier that Google returns for that account.
  • Task prompts you type into the dispatch box, and the agent replies, held in memory to render the activity feed.

All of it lives in a single file, antigravity.json, on the server's own disk. Nothing is written to a database, and nothing leaves the server except the API calls described below.

Why it is stored

The refresh token is kept so the service can continue calling Google's Gemini models on your behalf without asking you to sign in again after every restart. The email is kept only to display the active account and to enforce the account allowlist.

What the tokens are used for

Each task you dispatch is sent to Google's Cloud Code endpoints to generate the project manager, developer and reviewer responses. Tokens are not used for any other purpose. They are never sent to an analytics provider, an advertising network, or any third party.

Sharing

No data is sold, shared, or transferred to anyone. The service has no analytics, no tracking pixels, and no third-party scripts. Fonts fall back to system fonts if the external stylesheet is unavailable.

Retention and deletion

  • Deleting antigravity.json from the persistent volume removes the stored tokens from the server.
  • You can revoke the app's access at any time at myaccount.google.com/permissions. The next refresh attempt then fails and the local session is discarded.
  • Task logs live in memory only and disappear when the service restarts.

Security

The token file is written with owner-only permissions. The OAuth client secret is supplied through the host's environment variables and is not part of the public repository. Traffic runs over HTTPS on the deployed host.
